Reinforcement learning (RL) has become one of the dominant paradigms for optimizing modern machine learning systems, from AlphaGo to large language models and, more recently, diffusion models. Given an objective that can be evaluated—assume, for convenience, that we want to minimize it—a natural recipe is simple: treat the negative objective as a reward, sample solutions from a policy, and optimize the expected reward with RL.

This recipe is remarkably general. Variants of it have been used for reasoning, alignment, combinatorial optimization, and many other problems where direct supervision is scarce but an objective is available.

But it also raises a question that I find interesting:

> **If we know the objective function, is reinforcement learning the only way to learn from it?**

The answer is clearly **no**.

Over the past few years, a growing collection of methods has approached essentially the same problem from very different perspectives. In this post, I want to collect some of these ideas, including some of my own work, into a small gallery of methods beyond RL. The goal is not to argue that one paradigm dominates the others. Rather, I want to highlight the surprisingly different ways an objective function can be turned into a learning signal, and the connections between methods that can initially look quite unrelated.

Which approach works best depends strongly on the structure of the problem: Is the objective differentiable? Can we evaluate it only on complete solutions, or also on intermediate states? Is the policy autoregressive, diffusion-based, or a continuous-time process? Can we sample from it efficiently? These properties can make very different learning principles natural—and sometimes make RL only one option among many.

## 1. The Setup: Learning Without Solutions

Consider an optimization problem

$$
x^\star = \arg\min_x g(x),
$$

where we can evaluate the objective $g(x)$, but do not have a dataset of optimal solutions $x^\star$.

If optimal solutions were available, we could simply train a model with supervised learning. Without them, reinforcement learning provides an obvious alternative. Given a distribution $p_\theta(x)$, we might minimize

$$
\mathcal{L}(\theta) = \mathbb{E}_{x\sim p_\theta}[g(x)],
$$

and estimate its gradient through REINFORCE or other policy-gradient methods:

$$
\nabla_\theta \mathcal{L}(\theta) = \mathbb{E}_{x\sim p_\theta} \left[ g(x)\nabla_\theta\log p_\theta(x) \right].
$$

But this is only **one** way of exploiting $g(x)$.

Instead of asking how to construct a better policy gradient, we can ask a broader question:

> **What mathematical object can we construct from the objective, and how can we learn from that object?**

Different answers to this question lead to surprisingly different algorithms.

---

## 2. Connection between Optimization and Generation

The direct optimization of $g(x)$ is usually hard. We instead consider a soft version: turning the optimization problem into a sampling problem from the following **Energy-based Model (EBM):

$$
p_\beta(x) = \frac{1}{Z_\beta} \exp(-g(x)/\beta),
$$

where $Z_\beta$ is an intractable normalization factor, and $\beta$ controls how strongly the distribution concentrates around low-energy solutions.

As $\beta$ becomes small, probability mass increasingly concentrates on good solutions, recovering the original optimization problem.

In fact, this is just a special case that we use the uniform distribution as the prior. We can in fact generalize this to arbitrary prior distribution.

Define the following distribution:

$$\min_p \mathbb{E}_{x\sim p}[g(x)] + \frac{\beta \mathrm{KL}(p\| p^{0})$$,

which aims to optimize the original objective but stays close to a prior distribution $p^0$. There exists a closed-form solution:

$$p(x)\propto p^0(x)\exp(-\beta g(x))$$


How to sample from EBM is actually a long-standing problem, and the most classical method is called Markov-Chain Monte Carlo (MCMC). The key idea is to construct a following Markov Chain:

Each time we are at same $x_t$, we will sample a new (usually a nearby) state $x'$, if the the state $p(x')>p(x)$, we transit to $x'$ as $x_{t+1}=x'$; otherwise, we will only transit to $x'$ with certain probability.

One simple way to understand this process is to treat it as a hill-climbing process: each time we see if there is any way to climb higher, otherwise we select a lower state in order to avoid the local optima. 





A forward process gradually corrupts structured solutions into noise, while a learned reverse process attempts to reconstruct low-energy samples. The optimization problem is therefore transformed into learning a generative process.

Conceptually, this is already quite different from RL.

RL asks:

> Which actions should I reinforce to obtain higher reward?

The energy-based perspective asks:

> What distribution should I learn so that low-energy configurations become probable?

This connection between **optimization, statistical physics, and generative modeling** will appear repeatedly throughout this post.

## 3. SDDS: Learn the Boltzmann Distribution with Forward KL

Once we write down

$$
p_\beta(x) \propto \exp(-\beta E(x)),
$$

another question immediately appears:

> Why not directly fit a generative model to this distribution?

The difficulty, of course, is that we cannot directly sample from $p_\beta$. Its normalization constant is generally intractable, and obtaining samples from the target distribution is essentially the optimization problem itself.

**SDDS** provides another route.

Instead of relying on samples from the target distribution, it considers objectives based on the **forward KL divergence**

$$
D_{\mathrm{KL}}(p_\beta \Vert q_\theta).
$$

This direction of KL has an important property: it encourages the learned distribution to cover the modes of the target distribution rather than collapsing onto a small subset of solutions.

The interesting part is how this learning objective can be estimated even though direct samples from the target Boltzmann distribution are unavailable. By combining the known energy with diffusion-based sampling and importance-weighting ideas, the target distribution itself provides supervision.

So the overall picture becomes:

$$
E(x) \quad\rightarrow\quad p_\beta(x) \quad\rightarrow\quad \text{distribution matching}.
$$

There is no dataset of optimal solutions, and we do not need to formulate the problem as conventional RL.

The objective function defines a distribution, and **distribution matching becomes the learning problem**.

## 4. RLD4CO: Turn Optimization into Stochastic Control

There is another way to think about the same Boltzmann distribution.

Rather than directly learning its density, we can ask:

> Can we construct a stochastic process whose terminal distribution favors low-cost solutions?

This leads to the perspective of **RLD4CO**.

Consider a stochastic process that evolves from a simple initial distribution toward increasingly structured solutions. Instead of viewing the model merely as a generative model, we can view its dynamics as a **control problem**.

The objective determines a terminal cost, while the learned dynamics determine how probability mass should move through state space.

Schematically,

$$
\text{objective} \rightarrow \text{terminal cost} \rightarrow \text{optimal stochastic dynamics}.
$$

This connects discrete optimization to ideas from stochastic optimal control, path-space inference, and diffusion processes.

One appealing aspect of this view is that optimization is no longer reduced to assigning credit to individual sampled actions. The learning problem can instead be expressed in terms of the **entire dynamics of a stochastic process**.

This gives us a third perspective:

* RL: learn from sampled rewards;
* energy-based methods: learn a target distribution;
* stochastic control: learn dynamics that transport samples toward low-cost regions.

## 5. Adjoint Matching: Differentiate Through the Objective

The previous approaches largely treat the objective through the distribution it induces.

But suppose we know more than just the scalar value $E(x)$. Perhaps we can exploit how the objective changes when the state changes.

This motivates **Adjoint Matching (AM)**.

In continuous optimization, gradients tell us exactly this:

$$
\nabla_x E(x).
$$

Instead of waiting until the end of a trajectory to observe a scalar cost, we can propagate information about the terminal objective backward through the dynamics.

The mathematical language for doing this is the **adjoint**.

Very roughly, an adjoint tells us:

> If I perturb the state here, how will that perturbation affect the final objective?

This produces a much richer learning signal than a single scalar reward.

Rather than

$$
\text{trajectory} \rightarrow \text{terminal reward},
$$

we obtain something closer to

$$
\text{objective gradient} \rightarrow \text{backward sensitivity} \rightarrow \text{local training signal}.
$$

This is particularly attractive when the objective is known and differentiable. If the structure of the objective already tells us which direction improves the solution, throwing that information away and retaining only a scalar reward can be unnecessarily indirect.

## 6. CAM: Adjoint Matching in Discrete Space

But many interesting optimization problems are discrete.

For a binary state $x \in \{0,1\}^N$, the ordinary gradient $\nabla_x E(x)$ is not directly defined in the way we would like.

However, we can ask a discrete analogue of the same question:

> What happens to the objective if I flip one variable?

Define a flip difference

$$
\nabla_i^{\mathrm{flip}}E(x) = E(x^{(i)}) - E(x),
$$

where $x^{(i)}$ denotes the state obtained by flipping the $i$-th variable.

This simple quantity plays a role analogous to a gradient.

**Combinatorial Adjoint Matching (CAM)** builds on this observation. By representing discrete generation as a continuous-time Markov chain, we can derive a discrete analogue of adjoint dynamics and use the objective's local structure to supervise the generative process.

The conceptual transition from AM to CAM is therefore

$$
\nabla E(x) \quad\longrightarrow\quad \nabla^{\mathrm{flip}}E(x).
$$

Instead of estimating which decisions were good through noisy scalar rewards, CAM asks how individual discrete changes affect the objective and propagates this information through the generative dynamics.

This is perhaps the most direct example of the theme of this post:

> **When the objective contains structure, use that structure as supervision.**

## 7. Twisted Sequential Monte Carlo: Let the Objective Guide Sampling

There is yet another possibility.

Suppose we already have a generative model $p_\theta(x)$ that can produce candidate solutions. Rather than retraining the model itself, perhaps we can modify the **sampling procedure** so that samples are biased toward high-quality regions.

This is where **twisted Sequential Monte Carlo (SMC)** provides a useful perspective.

SMC constructs samples sequentially using a population of particles. At each stage, particles are propagated and reweighted according to their likelihood of eventually reaching desirable outcomes.

A **twisting function** modifies these intermediate distributions using information about the future objective.

Informally, instead of asking only

> How likely is this partial solution under my model?

we ask

> How promising is this partial solution given the objective I ultimately care about?

The objective therefore enters not necessarily as a training signal, but as a **sampling signal**.

This creates another route:

$$
E(x) \rightarrow \text{twisting potential} \rightarrow \text{guided sampling}.
$$

This distinction is useful. Sometimes we may not need to change the underlying model at all. A sufficiently powerful inference or sampling procedure can incorporate the objective at test time.

## 8. A Gallery of Ways to Use an Objective

Putting these methods next to each other reveals a pattern.

The same starting point,

$$
\boxed{\text{We know }E(x)\text{, but we don't know }x^\star}
$$

can lead to very different mathematical constructions.

| Method      | What do we construct from the objective? | What do we learn/do?                 |
| ----------- | ---------------------------------------- | ------------------------------------ |
| RL          | Reward                                   | Optimize expected reward             |
| DiffUCO     | Energy / Boltzmann distribution          | Learn a generative process           |
| SDDS        | Target Boltzmann distribution            | Minimize a distributional divergence |
| RLD4CO      | Terminal cost                            | Learn stochastic dynamics            |
| AM          | Objective gradient                       | Match adjoint dynamics               |
| CAM         | Discrete objective differences           | Match discrete adjoints              |
| Twisted SMC | Twisting potential                       | Guide particles during sampling      |

I find this comparison useful because these methods can look unrelated when encountered separately.

One paper talks about diffusion. Another talks about KL divergence. Another derives a stochastic control problem. Another introduces adjoint equations. Another uses sequential Monte Carlo.

But they are all answering variants of the same question:

> **How can we turn an objective function into useful information for learning or sampling?**

---

## 9. Beyond RL

RL has an enormous advantage: it makes very few assumptions.

If we can sample an output and evaluate a scalar reward, we can in principle optimize it. This generality is one reason RL has become so powerful.

But generality comes with a price. Reducing everything to a scalar reward can discard structure that we already know about the problem.

If the objective defines an energy, perhaps we can learn its Boltzmann distribution.

If it defines a terminal cost, perhaps we can formulate a stochastic control problem.

If its local changes can be evaluated, perhaps we can construct an adjoint.

If we have a good generative model already, perhaps we can inject the objective directly into sampling.

So perhaps the right question is not

> **RL or not RL?**

but rather

> **What information does the objective give us, and what is the best mathematical machinery for exploiting it?**

RL is one remarkably general answer.

But it is far from the only one.
